SCOPE: школьный сайт, все ученические интерфейсы, учебные задания, ИИ-роли, маршруты, создаваемые материалы и их обновления.

## Непересматриваемое рабочее правило
**Ни один новый/изменённый результат не объявлять готовым и не публиковать без проверки человеческой логики по всем 80 идентификаторам S14 Pattern Gate v1.1.** Исключения по области записывать как `NOT_APPLICABLE`, не пропускать молча. Проверку проводить ДО и ПОСЛЕ исправлений. Она обязательна и для ученических сценариев, и для сопровождения учителя.

## Рабочая цепочка
1. Прочитать текущий точный источник, целевую аудиторию, окружение и действующую задачу. Ничего не додумывать за источник.
2. Восстановить маршрут ученика от входа до наблюдаемого результата, включая устройство, навыки (файл/папка/браузер/ИИ/передача), точки выбора, состояния ошибки, запреты и доступность сервисов.
3. Прогнать **каждый из 80** паттернов: E01–E07; L01–L08; F01–F07; P01–P07; A01–A07; O01–O05; S01–S05; M01–M06; T01–T08; K01–K10; W01–W10. Для каждого сохранять applicability, evidence, finding, severity, disposition.
4. Удалить дубли, отделить доказанные дефекты от AI-гипотез и недостатка данных; составить один полный набор исправлений. Не выдумывать статистику учеников и не обещать полевой PASS.
5. Исправить точечно, сохранить исходное задание/промпт/авторство и обратную совместимость; добавить помощь «Не знаю как» там, где скрыта предпосылка, сохранение состояния/возврат и проверку результата.
6. Проверить изменённые файлы и сценарии: валидность HTML/CSS/JS, работающие клики/ссылки, мобильные ширины и экран компьютера, доступность с клавиатуры, запасной сценарий без нужного сервиса, риски приватности.
7. Провести **повторный полный прогон всех 80 паттернов**, зафиксировать delta и незакрытые риски. При записи в GitHub: exact file → write → readback (и Git SHA). Ни `READY`, ни `PUBLISHED` до доказуемого readback. Реальное отображение GitHub Pages подтверждать отдельно.
8. Только после gate выдавать результат с проверенными изменениями, ограничениями и ровно одним следующим действием. Если gate не пройден — `BLOCKED / NOT_VERIFIED`, не выдавать ложный PASS.

## Педагогические и операционные границы
- Сложность не должна скрыто требовать опыта: умение создавать папки, файлы, включать расширения, переключать приложения и отправлять результат не предполагается по возрасту.
- Перед каждым зависимым шагом есть необходимый контекст; помощь короткая, раскрывается по требованию, возвращает туда же, не выполняет учебную задачу вместо ребёнка.
- «Нажал кнопку» не означает «получил нужный артефакт», AI-ответ не означает «овладел навыком».
- Полевой тест не проводить без отдельного решения пользователя. Статическое/модельное доказательство никогда не называть результатом детей.
- Не публиковать персональные данные учеников, не просить пароли/токены, не стирать единственную копию и не удалять временную работу до подтверждения передачи.
- Публикация/release только при явном разрешении. Если нет актуального доступа к файлам/источникам — помечать `NOT_VERIFIED`, не заменять проверку предположением.
- Один bounded review → один полный набор дефектов → один ремонт → один контрольный повтор, если нет материального основания расширять.
