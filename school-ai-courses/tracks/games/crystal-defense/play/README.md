# Кристальный рубеж · пилот многофайловой игры

**Назначение:** продвинутый этап разработки игр 7–9; пока используем только «Кристальный рубеж» для испытания подхода. Другие две игры не меняем.

```text
Кристальный рубеж/
  index.html           — структура игрового экрана
  game.css             — визуальное оформление и адаптация
  art.js               — карта, башни, враги и анимационная отрисовка Canvas
  game.js              — игровые правила, обработка ввода, валюта и волны
  game.json            — настройки и пути к ресурсам (на сайте / http)
  config.offline.js    — резерв настроек для запуска file://
  assets/
    ASSETS_LICENSES.md — происхождение и лицензии
    kenney/
      flare.png
      magic.png
      bush.png
      bush-orange.png
```

## Как запустить

1. **На сайте:** откройте игру — браузер загрузит `game.json` и ресурсы сам.
2. **Без интернета:** скопируйте всю папку и откройте `index.html`. Игра использует `config.offline.js` и локальные картинки.
3. **Если меняете `game.json` в папке на компьютере:** обновите те же значения в `config.offline.js`, иначе двойной щелчок не увидит изменения JSON.
4. **Если нужен автоматический режим JSON на школьном ПК:** запустите локальный HTTP-сервер в папке игры, только если он уже есть и запуск разрешён политикой учреждения (пример для установленного Python: `py -m http.server 8000`), затем откройте `http://localhost:8000/`. Для обычного занятия установка Python НЕ требуется.
5. Проверьте внизу страницы индикатор: откуда загружены настройки, сколько изображений найдено. Если файл отсутствует, игра продолжает работать с программной графикой.

## Сценарий для ученика

- Выбери авторский стиль и нарисуй/найди **1–2** подходящих ресурса.
- Сравни разрешение, размер файла и прозрачность.
- Запиши источник, автора и лицензию в `assets/ASSETS_LICENSES.md`.
- Сохрани в `assets/`, обнови путь в `game.json` и `config.offline.js` для локального запуска.
- Сравни игру на ПК и смартфоне: нет ли искажений, обрезания, промахов касания, долгой загрузки.
- Улучши одну деталь, но не заменяй код всей игры ради одного изображения.

## Как просить ИИ по файлам

Не требуйте всего проекта одним ответом. Дайте ИИ дерево папок и один конкретный файл для изменения.
Попросите: «Не изменяй публичные имена функций и пути, внеси одно улучшение, верни полный обновлённый *только этот* файл и перечисли тесты».
Изменения структуры или формата JSON согласовывайте отдельно. Красоту оценивайте визуально после реального запуска.

**Заметка:** иллюстрации Kenney — свободные CC0, однако сквозной оригинальный визуальный стиль нашей игры сохранён; PNG используются для эффекта и окружения как дополняющие слои, а не для замены всего художественного оформления.

## Баланс и ускорение (версия 3.1)

- Кнопка **×1** последовательно переключает **×1 → ×2 → ×3 → ×4 → ×5 → ×1**. Ускорение меняет **ход времени**, а не множитель силы врагов. Для корректных попаданий время делится на короткие шаги симуляции.
- По умолчанию: **9 здоровья**, **195 кристаллов** и **не более 9 башен** одновременно. Продать башню и построить новую можно.
- После первых волн противники становятся прочнее и быстрее; состав атак растёт с 8 до 26 существ. Важны расположение, своевременные улучшения и применение импульса.
- Все ключевые параметры доступны в `game.json` и `config.offline.js`: `startGold`, `startHealth`, `maxTowers`, `waveEnemyHealthGrowth`, `waveEnemySpeedGrowth`, `spawnIntervalMultiplier`.
- **Проверка сложности:** только две башни без развития не способны защитить ядро до конца; девять башен без улучшений могут проиграть финальную волну. При улучшениях победа достижима. Это подтверждено моделированием игровой логики, но не означает полевой приёмки.

Для ученических вариантов сначала изменяйте один параметр баланса, затем проверяйте проигрыш и победу при разных стратегиях. Красивый интерфейс не заменяет игровую трудность.
