1

Разбери игру как разработчик

Задача: сыграй в готовый «Кристальный рубеж» до второй волны. Не копируй реализацию; сначала пойми, как создаётся такой игровой процесс и почему он выглядит цельно.

Обрати внимание на три системы: игровые правила (валюта, волны, урон), художественная сцена (фон, башни, частицы, свет) и интерфейс (строительство мышью/касанием, панели, подсказки). На смартфоне обрати внимание на отдельную панель башен над игровым полем.

Попробуй самостоятельно восстановить устройство игры по наблюдениям. Затем сверь свою гипотезу с архитектурой образца и исходниками проекта.

Что должно получиться к концу шага:
  1. Короткое описание игрового цикла: подготовка → волна → награда → улучшение → следующая волна.
  2. Свой художественный замысел: тема мира, палитра и визуальная особенность противников/башен.
  3. Одно собственное изменение механики с проверяемым эффектом, например «новая башня оглушает только быстрых врагов на 1 секунду», а не просто «сделай красиво».

Это продвинутый уровень. Работа с папками, расширениями и Блокнотом считается освоенной; здесь важны проектирование, интеграция, качество и проверка.

2

Выбери реальные изображения и проверь лицензии

Ищи игровые ресурсы, а не случайные картинки из поиска. Начни с проверенных бесплатных библиотек:

Kenney · Tower DefenseБашни, объекты, тайлы · CC0 Kenney · Particle PackСвет, попадания, вспышки · CC0 Kenney · BackgroundsОкружение и декорации · CC0 OpenGameArtПроверяй лицензию каждого файла
  1. Выбери один художественный стиль. Не смешивай несовместимые пиксельные и реалистичные картинки.
  2. Скачай ZIP с выбранного ресурса, открой его и скопируй 2–4 отдельные PNG/WebP в assets/kenney/ или собственную подпапку.
  3. Посмотри фактические ширину × высоту, тип файла и размер в КБ через «Свойства → Подробно».
  4. Запиши автора, ссылку и лицензию в assets/ASSETS_LICENSES.md. Не приписывай CC0 чужому набору автоматически.
Ориентиры учебного проекта: изображение обычно 64–512 пикселей по большей стороне, один файл желательно до 250 КБ, вся графика до 600 КБ. Это рекомендации для быстрой загрузки, а не ограничения браузера. Для персонажей и эффектов важна прозрачность PNG/WebP. Интерфейс должен оставаться читаемым и на экране 360 пикселей.
У меня пока нет ресурсов или сеть не работает

Скопируй файлы из уже подготовленного проекта с разрешения учителя или пока используй программную графику Canvas. Техническую недоступность сети запиши отдельно; запрещено обходить школьные ограничения.

3

Попроси ИИ создавать проект по одному файлу

Это уже не запрос «напиши 25 тысяч строк за раз». Сначала дай ИИ архитектуру и своё оригинальное изменение, затем запроси отдельные файлы. Важна согласованность интерфейсов: имена функций, идентификаторы элементов и формат JSON не должны внезапно меняться между ответами.

Порядок построения (не порядок создания папок):
  1. Контракт: перечисли состояния игры, объекты, структуру JSON и связи art.js ↔ game.js. Результат — компактная схема без кода.
  2. Каркас: index.html и game.css. Сначала проверь дизайн с пустой игровой сценой на широком и узком экране.
  3. Конфигурация: game.json, а для запуска с диска — зеркальный config.offline.js. Проверь совпадение значений.
  4. Художественный слой: art.js, использующий изображения из assets/ и Canvas для эффектов.
  5. Игровой движок: game.js. Сначала одна башня + один враг + одна волна, затем экономика, три башни и пять волн.
  6. Сборка: проверка связей и функциональных сценариев после каждого компонента, а не после огромного финального ответа.
Готовые короткие команды для следующих этапов

После согласования контракта: отправляй по одной команде в том же диалоге, сохраняя имена файлов и их обязанности.

  • Создай index.html — подключи CSS и скрипты в согласованном порядке; добавь реальное поле Canvas, счётчики, доступное управление, мобильную панель.
  • Создай game.css — сделай авторскую дизайн-систему и адаптивность 360/390/768/1366 px, не изменяя ID из index.html.
  • Создай game.json, затем config.offline.js — значения и пути должны совпадать; не встраивай PNG внутрь JSON.
  • Создай art.js — Canvas-отрисовка и загрузка локальных ассетов; соблюдай контракт с игровым движком.
  • Создай game.js — реализуй сначала проверяемый срез и затем остальные волны, не переписывая art.js.
  • Проверь интеграцию — назови пять наблюдаемых тестов с указанием ожидаемого и фактического результата.

Последовательность файлов ИИ: index.html → game.css → game.json → config.offline.js → art.js → game.js. После каждого ответа сохраняй файл, а не копируй все блоки подряд в один документ. Изображения ИИ не должен выдавать в виде длинного Base64 — их получаем из библиотеки.

ИИ отвечает «Продолжить» и код обрывается

Напиши: «Остановись. Проверь, что в текущем ответе полный файл, от первой до последней строки. Если он слишком велик, предложи разделить game.js на отдельные согласованные модули без потери интерфейсов». Нельзя склеивать два куска кода наугад. Для школьного запуска без сервера используй обычные подключаемые скрипты, не ES-модули.

4

Запусти проект, проверь графику и два экрана

Сначала открой index.html двойным щелчком в браузере. Он должен использовать локальную конфигурацию config.offline.js. На опубликованном сайте настройки берутся из game.json.

Файлы должны лежать вместе, точно в указанной структуре. Если изображения не найдены, сравни относительные пути и регистр букв. В образце открой раздел «Ресурсы проекта» — он покажет, сколько файлов реально загрузилось.

Если при локальном запуске JSON не загружается — не отключай защиту браузера. Используй config.offline.js, а чтение JSON через fetch проверь на опубликованном сайте или разрешённом локальном сервере.

Как подтвердить реальные размеры изображения?

В Windows открой свойства PNG → «Подробно» (ширина и высота в пикселях), затем свойства файла → размер в КБ. Сравни с размером игрового объекта: если маленький элемент приходится очень сильно растягивать, найди более крупный спрайт; если крошечный значок весит мегабайты — оптимизируй ресурс.

5

Исправь один недостаток и собери новую версию

Версия 2 должна быть измеримо лучше версии 1. Выбери один наблюдаемый дефект: слабый контраст, непропорциональные спрайты, слишком тяжёлый PNG, ошибка пути, дисбаланс экономики, промах касания. Сохрани предыдущую работающую версию.

Отправь ИИ только необходимый контекст: наблюдение, ожидаемое поведение, затронутый файл и интерфейсы, которые нельзя менять. Потребуй полный исправленный один файл, список зависимостей и способ воспроизвести дефект. Сравни старую и новую версии на ПК и смартфоне.

Критерии завершения: игра запускается без обязательного сервера, все картинки загружаются из assets/, есть пять проходимых волн и состояния победы/поражения, интерфейс пригоден для мыши и касаний, использованные ресурсы лицензированы, ZIP содержит всю структуру проекта.

Запиши: исходный вид → какое действие выполнено → изменённый результат → ограничения. Хорошая картинка без работающей игровой механики не считается готовым проектом.

Сохрани весь проект, не один HTML-файл

Итог — папка проекта со всеми файлами: HTML, CSS, JS, JSON, локальные настройки, картинки и сведения об источниках. Если при переносе пропала папка assets, графика исчезнет.

  1. Проверь, что внутри нет паролей, ключей API или персональных данных.
  2. На своей копии проекта сделай ZIP всей папки и убедись, что внутри архива есть assets/.
  3. Передай ZIP преподавателю в согласованный чат MAX или другим утверждённым способом. Если передача не работает — сохрани копию и сообщи об этом отдельно.
  4. Не удаляй единственный экземпляр до подтверждения приёма и сохранения работы.

Для примера посмотри рабочую игру, её структуру проекта и перечень ресурсов. Не копируй пример вместо собственной попытки.
